* Objectifs de la séance

En séance 2, le calcul de tranche de revenu a été recopié deux fois. Recopier
du code est toujours le signe qu'il manque une abstraction : c'est le rôle des
*fonctions*.

À l'issue de la séance, vous saurez :

- définir une fonction, lui passer des *arguments*, en récupérer une *valeur
  de retour* ;
- donner des *valeurs par défaut* à certains arguments ;
- distinguer les variables *locales* des variables *globales* ;
- importer un *module* et vous repérer dans la bibliothèque standard ;
- intercepter une erreur avec =try= / =except= ;
- manipuler un tableau *NumPy* et comprendre ce qu'est une opération
  vectorisée.

Deux idées gouvernent cette séance, et elles se rejoignent.

La première est qu'*un code qu'on recopie est un code qu'on maintiendra mal*.
À la séance précédente, le classement par tranche de revenu a été écrit deux
fois : une fois pour un salarié, une fois dans une boucle. Le jour où les
seuils changent — et ils changeront, le SMIC est révisé chaque année — il
faudra les corriger aux deux endroits, et l'on en oubliera un. Une fonction
règle le problème en donnant un *nom* au calcul : on le corrige à un seul
endroit, et tous les appels en bénéficient.

La seconde est qu'*on écrit du code pour le relire*. Vous rendrez un notebook
de projet que je lirai, que vos coéquipiers liront, et que vous relirez
vous-mêmes après plusieurs semaines d'interruption. Ce qui vous paraît
évident aujourd'hui ne le sera plus. Les fonctions bien nommées, les
docstrings et les commentaires qui expliquent le /pourquoi/ ne sont pas des
politesses : ce sont les seules choses qui rendent un travail reproductible,
et la reproductibilité est explicitement ce qu'on attend de vous.

* Définir une fonction

#+BEGIN_SRC python
def salaire_net(brut, taux_cotisations=0.22):
    """Calcule le salaire net à partir du brut.

    brut             : salaire brut mensuel, en euros
    taux_cotisations : part des cotisations salariales (0.22 par défaut)
    """
    return brut * (1 - taux_cotisations)


# Appels : le second argument est facultatif.
print(salaire_net(2500))
print(salaire_net(2500, 0.25))
print(salaire_net(brut=4200, taux_cotisations=0.25))    # arguments nommés
#+END_SRC

Décomposons. =def= introduit la définition et le nom. Ce qui suit entre
parenthèses, ce sont les *paramètres*. Le deux-points ouvre le corps, qui est
indenté comme celui d'un =if=. =return= renvoie le résultat à l'appelant et
termine la fonction.

Le texte entre triples guillemets est la *docstring* : elle documente la
fonction et s'affiche avec =help(salaire_net)=. Prenez l'habitude de
l'écrire — c'est ce que vous relirez dans six mois.

=taux_cotisations=0.22= est une *valeur par défaut* : le paramètre devient
facultatif. Enfin, on peut passer les arguments *par nom*, ce qui rend
l'appel autodocumenté et dispense de retenir leur ordre.

Une variable créée dans une fonction est *locale* : elle disparaît à la sortie.
C'est une protection, pas une gêne — c'est ce qui permet d'écrire une fonction
sans craindre d'écraser une variable du reste du programme.

* Modules et bibliothèque standard

Un *module* est un fichier de code que l'on charge avec =import=. Python en
livre plusieurs centaines : c'est la bibliothèque standard.

#+BEGIN_SRC python
import math
import statistics

salaires = [1850, 2100, 2450, 1650, 3200, 2050, 1900]

print(statistics.mean(salaires))        # moyenne
print(statistics.median(salaires))      # médiane
print(round(statistics.stdev(salaires), 2))

print(math.log(2500))                   # logarithme népérien
print(math.sqrt(144))
#+END_SRC

Un point de vocabulaire utile pour la suite : =statistics.mean= se lit
« la fonction =mean= du module =statistics= ». Le point sert ici à naviguer
dans un module, comme il servait en séance 2 à appeler une méthode d'objet.
C'est la même notation pour deux idées voisines — « ce qui appartient à ».

Notez surtout que =statistics.stdev= calcule l'écart-type *d'échantillon*,
celui qui divise par /n−1/, et non l'écart-type de population
(=statistics.pstdev=). L'écart est négligeable sur cinq mille observations et
franchement visible sur sept. Vérifier quelle convention adopte une fonction
avant de publier un chiffre est un réflexe qui vous évitera des surprises —
et il vaut pour toutes les bibliothèques, pandas compris.

Trois formes d'import coexistent. =import math= charge le module et impose de
préfixer (=math.log=). =from math import log= importe un seul nom, utilisable
sans préfixe. =import pandas as pd= charge sous un alias — c'est la forme que
vous verrez partout en séance 4.

#+BEGIN_SRC python

* Gérer les erreurs

Une erreur interrompt le programme. =try= / =except= permet de l'intercepter
et de poursuivre — indispensable quand on traite des milliers de lignes dont
quelques-unes sont douteuses.

#+BEGIN_SRC python
# Des salaires tels qu'ils sortiraient d'un fichier : du texte, et des trous.
brut = ["2500", "2 800", "", "3100", "non renseigné", "1950"]

valides = []
for valeur in brut:
    try:
        valides.append(float(valeur))
    except ValueError:
        print(f"Valeur ignorée : {valeur!r}")

print(valides)
print(f"{len(valides)} valeurs exploitables sur {len(brut)}")
#+END_SRC

Notez ={valeur!r}= : le =!r= affiche la valeur telle que Python la voit,
guillemets compris — c'est ce qui rend visible la chaîne vide.

Une mise en garde : n'interceptez que les erreurs que vous attendez, ici
=ValueError=. Un =except= sans précision masquerait aussi les fautes de frappe
et les vrais bogues, et vous chercheriez longtemps.

* Qualité du code

Un code propre est un code réutilisable. Trois principes suffisent à ce stade.

*Nommer pour être lu.* =taux_croissance= vaut mieux que =tc=. Le temps gagné
à la frappe est perdu au centuple à la relecture.

*Commenter le pourquoi, pas le quoi.* =# on multiplie par 12= est inutile, le
code le dit déjà. =# le treizième mois est versé en décembre, d'où 13= est
utile : il explique une décision qui ne se lit pas dans le code.

*Une fonction, une responsabilité.* Si vous ne pouvez pas décrire ce que fait
votre fonction en une phrase, c'est qu'il y en a deux.

#+BEGIN_SRC python
# Version peu lisible
def f(x, y):
    return (1 - x / y) * 100


# Version lisible : le nom et la docstring disent tout
def ecart_relatif(valeur, reference):
    """Écart de « valeur » à « reference », en % de la référence."""
    return (1 - valeur / reference) * 100


print(ecart_relatif(1980, 2450))
#+END_SRC

Les deux fonctions calculent rigoureusement la même chose. La première oblige
à remonter au code pour savoir ce qu'elle fait et dans quel ordre passer les
arguments ; la seconde le dit d'elle-même. Le coût de la clarté s'est limité à
quelques secondes de frappe, une fois.

Un dernier conseil, qui vous servira surtout dans le projet : quand une
fonction devient longue, demandez-vous si elle ne fait pas deux choses. Une
fonction qui « nettoie les données et calcule la moyenne » gagne presque
toujours à devenir deux fonctions — parce qu'on voudra un jour nettoyer sans
calculer la moyenne.

* Première approche de NumPy

*NumPy* fournit le =array=, un tableau de nombres sur lequel les opérations
s'appliquent *à tous les éléments à la fois*. C'est la brique sur laquelle
pandas est construit : le comprendre ici évite de le subir en séance 4.

#+BEGIN_SRC python
import numpy as np

salaires = np.array([1850, 2100, 2450, 1650, 3200, 2050, 1900])

# Pas de boucle : l'opération porte sur tout le tableau.
print(salaires * 1.02)
print(salaires - 1426.30)

print(salaires.mean())
print(salaires.std())
print(np.median(salaires))
#+END_SRC

Comparez avec la séance 2. Pour augmenter tous les salaires de 2 %, il
fallait une boucle et un accumulateur ; ici, =salaires * 1.02= suffit.
L'opération s'applique d'un coup à tous les éléments : c'est la
*vectorisation*, et c'est le trait qui distingue un tableau NumPy d'une liste.
Sur une liste ordinaire, =* 1.02= aurait échoué — et =* 3= aurait fait quelque
chose de tout différent, en répétant la liste trois fois.

Le gain n'est pas seulement d'écriture. Les boucles Python sont lentes ; les
opérations NumPy s'exécutent en code compilé, souvent cent fois plus vite. Sur
sept salaires, cela n'a aucune importance. Sur les centaines de milliers de
lignes d'une enquête Emploi, c'est la différence entre une seconde et deux
minutes — et c'est la raison pour laquelle pandas repose sur NumPy.

Une réserve utile : =.mean()= et =.std()= sont des méthodes du tableau, mais
=np.median()= est une fonction du module. Cette incohérence est un héritage
historique, elle n'a pas de logique — quand un doute survient, la
documentation tranche plus vite que l'intuition.

Avec une liste, =salaires * 1.02= aurait échoué : c'est le tableau NumPy qui
donne un sens à l'opération terme à terme. C'est ce qu'on appelle la
*vectorisation* — plus court à écrire, et bien plus rapide.

Le filtrage suit la même logique, et c'est celui de la séance 4 : une
comparaison produit un tableau de booléens, qui sert ensuite de masque.

#+BEGIN_SRC python
import numpy as np

salaires = np.array([1850, 2100, 2450, 1650, 3200, 2050, 1900])

masque = salaires < 2100          # un booléen par élément
print(masque)

print(salaires[masque])           # on ne garde que les « True »
print(masque.mean())              # la moyenne d'un booléen est une PART
#+END_SRC

Détaillons la dernière ligne, car elle sert constamment. En Python, =True=
vaut 1 et =False= vaut 0 dans un calcul. La moyenne d'un tableau de booléens
est donc le nombre de =True= divisé par l'effectif : une *proportion*. Écrire
=(salaires < 2100).mean()= répond en une expression à la question « quelle
part de l'échantillon gagne moins de 2 100 € ? ».

C'est exactement ce que vous écrirez en pandas dès la séance prochaine, sous
la forme =(df["salaire"] < 2100).mean()=. La syntaxe ne changera pas d'un
caractère : seul le tableau NumPy devient une colonne de DataFrame.

La dernière ligne mérite d'être retenue : la moyenne d'un tableau de booléens
est la *proportion* de valeurs vraies. C'est le moyen le plus court de
calculer une part.

* Mini-projet : une boîte à outils salariale

Rassemblez la séance en un petit ensemble de fonctions réutilisables, puis
appliquez-les à une liste de salariés. Votre boîte à outils doit contenir :

1. =net_a_payer(brut, taux_cotisations=0.22, taux_impot=0.05)= ;
2. =tranche(salaire)=, reprise de l'exercice 3.2 ;
3. =resume(salaires)= qui renvoie un *dictionnaire* contenant effectif,
   moyenne, médiane, minimum et maximum ;
4. un affichage lisible du résumé pour une liste de salaires bruts.

#+BEGIN_SRC python :corrige t
import statistics


def net_a_payer(brut, taux_cotisations=0.22, taux_impot=0.05):
    """Net à payer : cotisations puis prélèvement à la source.

    Les deux prélèvements se composent, ils ne s'additionnent pas.
    """
    net_avant_impot = brut * (1 - taux_cotisations)
    return net_avant_impot * (1 - taux_impot)


def tranche(salaire):
    """Classe un salaire mensuel net en trois tranches."""
    if salaire < 1600:
        return "Bas salaire"
    elif salaire < 2600:
        return "Salaire intermédiaire"
    return "Salaire élevé"


def resume(salaires):
    """Statistiques descriptives d'une liste de salaires."""
    return {
        "effectif": len(salaires),
        "moyenne": statistics.mean(salaires),
        "mediane": statistics.median(salaires),
        "minimum": min(salaires),
        "maximum": max(salaires),
    }


# --- Application ------------------------------------------------------
bruts = [2500, 2800, 1900, 4200, 3100, 1750, 2250, 5400]
nets = [net_a_payer(b) for b in bruts]

stats = resume(nets)
print("Salaires nets à payer")
print("-" * 34)
for cle, valeur in stats.items():
    print(f"{cle:10s} : {valeur:9.2f}")

print()
effectifs = {}
for net in nets:
    cle = tranche(net)
    effectifs[cle] = effectifs.get(cle, 0) + 1

for cle, nombre in effectifs.items():
    print(f"{cle:22s} : {nombre}")
#+END_SRC

* Ce qu'il faut retenir

- Une *fonction* porte un nom, reçoit des arguments et =return= un résultat ;
  ses variables sont locales.
- Une *valeur par défaut* rend un argument facultatif ; les *arguments
  nommés* rendent l'appel lisible.
- =import module= charge du code déjà écrit ; =import pandas as pd= est la
  forme que vous verrez partout.
- =try= / =except ValueError= laisse un traitement se poursuivre malgré
  quelques valeurs douteuses — n'interceptez que ce que vous attendez.
- Un tableau *NumPy* s'opère d'un bloc ; un masque booléen filtre, et la
  moyenne d'un masque est une part.

** Indexation et slicing

*Les indices commencent à zéro.* C'est la source d'erreur numéro un chez les
débutants, et elle ne disparaît qu'avec la pratique.

#+BEGIN_SRC python
salaires = [1850, 2100, 2450, 1650, 3200, 2050, 1900]

print(salaires[0])      # le PREMIER élément
print(salaires[2])      # le troisième
print(salaires[-1])     # le dernier
print(salaires[-2])     # l'avant-dernier

# Slicing : une tranche [début:fin], la fin étant EXCLUE
print(salaires[0:3])    # les trois premiers
print(salaires[:3])     # idem, le début est implicite
print(salaires[4:])     # du cinquième à la fin
#+END_SRC

La borne de fin est *exclue* : =salaires[0:3]= donne trois éléments, ceux
d'indices 0, 1 et 2. Cette convention paraît arbitraire ; elle a l'avantage
que =salaires[:k]= et =salaires[k:]= découpent exactement la liste en deux.

** Modifier une liste

#+BEGIN_SRC python
salaires = [1850, 2100, 2450]

salaires.append(1750)          # ajouter à la fin
salaires[0] = 1880             # remplacer un élément
print(salaires)

salaires.sort()                # trier sur place
print(salaires)
print(min(salaires), max(salaires), sum(salaires))
#+END_SRC

* Tuples, dictionnaires, ensembles

Un *tuple* s'écrit entre parenthèses et ne peut plus être modifié. On s'en
sert pour ce qui ne doit pas changer : des coordonnées, un couple de bornes.

#+BEGIN_SRC python
tranche_smic = (1426, 1800)     # bornes d'une tranche de revenu
print(tranche_smic[0], tranche_smic[1])

Un *dictionnaire* associe des *clés* à des *valeurs*. C'est la structure la
plus utile du langage : elle décrit naturellement un individu, où chaque
variable porte un nom.

#+BEGIN_SRC python
salarie = {
    "sexe": "Femme",
    "age": 34,
    "diplome": "Bac+5 ou plus",
    "salaire": 2850,
}

print(salarie["diplome"])            # accès par clé
salarie["anciennete"] = 6            # ajout d'une clé
print(salarie.keys())
print(salarie.values())
#+END_SRC

Un *ensemble* (=set=) est une collection sans ordre et *sans doublon*. Il
répond à une question précise : quelles sont les modalités distinctes ?

#+BEGIN_SRC python
diplomes = ["Bac", "Bac+5", "CAP-BEP", "Bac", "Bac+5", "Bac"]

print(set(diplomes))            # les modalités distinctes
print(len(set(diplomes)))       # combien y en a-t-il ?
#+END_SRC

* Les conditions

#+BEGIN_SRC python
salaire = 1380
smic_net = 1426.30

if salaire < smic_net:
    print("En dessous du SMIC net.")
elif salaire < 2100:
    print("Entre le SMIC et le salaire médian.")
else:
    print("Au-dessus du salaire médian.")
#+END_SRC

Deux règles de syntaxe, non négociables en Python. La ligne du =if= se termine
par un *deux-points*. Le bloc qui en dépend est *indenté* de quatre espaces :
c'est l'indentation, et elle seule, qui délimite le bloc. Un décalage d'un
espace est une erreur.

Les branches sont examinées dans l'ordre et *la première vraie l'emporte* :
dans l'exemple, un salaire de 1 380 € ne déclenche jamais le =elif=, même si
la condition est vraie elle aussi.

* Les boucles

** La boucle =for=

#+BEGIN_SRC python
salaires = [1850, 2100, 2450, 1650, 3200]

for salaire in salaires:
    print(f"Salaire : {salaire} €")
#+END_SRC

=range()= engendre une suite d'entiers — utile pour répéter un nombre connu
de fois. Comme le slicing, la borne de fin est exclue.

#+BEGIN_SRC python
# Projection d'un salaire sur 5 ans à 1,8 % par an.
salaire = 2000

for annee in range(1, 6):
    salaire = salaire * 1.018
    print(f"Année {annee} : {salaire:.2f} €")
#+END_SRC

** Accumuler dans une boucle

C'est le motif central de la séance : on prépare un accumulateur avant la
boucle, on l'alimente à chaque tour, on l'exploite après.

#+BEGIN_SRC python
salaires = [1850, 2100, 2450, 1650, 3200, 2050, 1900]

total = 0
for salaire in salaires:
    total = total + salaire

moyenne = total / len(salaires)
print(f"Masse salariale : {total} €")
print(f"Salaire moyen   : {moyenne:.2f} €")
#+END_SRC

** La boucle =while=

=while= répète tant qu'une condition reste vraie. On l'emploie quand le
nombre de tours n'est pas connu d'avance.

#+BEGIN_SRC python
# Combien d'années pour que ce salaire rattrape le salaire médian ?
salaire = 1700
median = 2100
annees = 0

while salaire < median:
    salaire = salaire * 1.018
    annees = annees + 1

print(f"{annees} ans (salaire final : {salaire:.2f} €)")
#+END_SRC

Attention : si la condition ne devient jamais fausse, la boucle tourne
indéfiniment. Vérifiez toujours que la variable testée est bien modifiée dans
le corps de la boucle.

* Ouverture : les compréhensions de listes

Une *compréhension* construit une liste en une ligne. C'est l'idiome le plus
caractéristique de Python, et il prépare directement la logique de pandas.

#+BEGIN_SRC python
salaires = [1850, 2100, 2450, 1650, 3200, 2050, 1900]

# Une augmentation de 2 % pour tout le monde.
augmentes = [round(s * 1.02, 2) for s in salaires]
print(augmentes)

# Avec un filtre : uniquement les salaires sous la médiane.
bas = [s for s in salaires if s < 2100]
print(bas)
#+END_SRC

Lisez =[s * 1.02 for s in salaires]= comme « =s * 1.02=, pour chaque =s= de
=salaires= ». La version longue avec =for= et =append= fait exactement la même
chose en quatre lignes. Retenez surtout la *forme filtrée* : c'est très
précisément ce que vous écrirez en séance 4 sous la forme
=df[df["salaire"] < 2100]=.

* Ce qu'il faut retenir

- *Liste* pour une suite ordonnée et modifiable, *tuple* pour ce qui ne doit
  pas changer, *dictionnaire* pour associer des noms à des valeurs,
  *ensemble* pour les modalités distinctes.
- Les indices commencent à *zéro* et la borne de fin d'une tranche est
  *exclue*.
- =if= / =elif= / =else= : deux-points, puis bloc indenté ; la première
  branche vraie l'emporte.
- Le motif « accumulateur avant la boucle, alimenté dans la boucle, exploité
  après » résout la plupart des calculs descriptifs.
- Une *compréhension filtrée* est l'ancêtre direct du filtrage pandas.
